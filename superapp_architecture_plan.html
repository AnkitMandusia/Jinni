Product Roadmap

From MVP to full multi-module super-app in 3 phases

Phase 1 — MVP (Months 1–4) MVP
Food Delivery: Multi-restaurant listings, menu browsing, cart, order placement, order tracking, restaurant/vendor onboarding
Grocery (In-house): App-owned product catalog, categories, inventory mgmt, cart, checkout
Core Infrastructure: User auth (JWT + OTP), Razorpay + COD payments, Firebase push notifications, basic admin panel, PostgreSQL schema
Deliverables: React Native app (Android + iOS), FastAPI backend, Admin panel (React + Ant Design)
Phase 2 — Growth (Months 5–8) Expansion
Cab Booking: Google Maps integration, real-time driver tracking, ride requests, fare estimation
Enhanced Food: Restaurant ratings/reviews, promo codes, scheduled delivery, loyalty points
Enhanced Grocery: Flash sales, subscription orders, substitution logic
Operations: Analytics dashboard, delivery partner app, SLA monitoring, CI/CD maturity
Phase 3 — Super-App (Months 9–14) Scale
Salon/Barber Services: Slot booking, stylist profiles, service catalog, in-home or in-store
Module Framework: Plugin-style service loader, universal service card component, shared cart across services
Infrastructure Scale: Redis caching, Celery async tasks, microservice split, Kubernetes deployment, multi-region
Platform: Partner SDK, webhook system, third-party service integration API

Key Design Patterns

Module Registry Pattern

Each service module exports a ModuleConfig object with: id, name, icon, HomeCard component, navigator. The HomeScreen dynamically renders registered modules — adding a new service only requires registering it in moduleRegistry.ts, no HomeScreen changes needed.

Universal Cart

The cart store holds a moduleType field ('food' | 'grocery' | 'cab' | 'salon'). Switching modules warns the user if there are items from a different module. At checkout, the unified CartScreen renders module-specific line items, delivery info, and payment options.

Authentication Flow

# JWT + OTP Strategy
POST /api/v1/auth/send-otp   → send SMS OTP via Twilio/MSG91
POST /api/v1/auth/verify-otp → verify OTP → return access_token + refresh_token
POST /api/v1/auth/refresh    → refresh access token
POST /api/v1/auth/logout     → blacklist refresh token (Redis)

# Dependency injection
async def get_current_user(token: str = Depends(oauth2_scheme), db = Depends(get_db)):
    payload = jwt.decode(token, SECRET_KEY, algorithms=["HS256"])
    user = await db.get(User, payload["sub"])
    return user

Grocery Inventory Service

# app/modules/grocery/service.py
class GroceryInventoryService:
    async def update_stock(self, product_id: UUID, delta: int, db: AsyncSession):
        """Atomic stock decrement on order placement"""
        result = await db.execute(
            update(Product)
            .where(Product.id == product_id, Product.stock_quantity >= abs(delta))
            .values(stock_quantity=Product.stock_quantity + delta)
            .returning(Product)
        )
        if not result.scalar_one_or_none():
            raise HTTPException(409, "Insufficient stock")

    async def get_low_stock_alerts(self, threshold: int = 10, db: AsyncSession):
        return await db.execute(
            select(Product).where(Product.stock_quantity <= threshold)
        )

import googlemaps
gmaps = googlemaps.Client(key=GOOGLE_MAPS_API_KEY)

def get_distance_and_eta(origin: tuple, destination: tuple):
    result = gmaps.distance_matrix(
        origins=[origin], destinations=[destination], mode="driving"
    )
    element = result["rows"][0]["elements"][0]
    return {
        "distance_km": element["distance"]["value"] / 1000,
        "eta_mins": element["duration"]["value"] // 60

Future Module Expansion

Adding new services without rewriting core infrastructure

The Module Contract

Every service module must implement a standard interface. This is enforced via a BaseModule abstract class in both backend and frontend. Adding a new service = implementing the contract + registering the module. Zero changes to shared infrastructure.

# Backend: app/modules/base.py
from abc import ABC, abstractmethod

class BaseServiceModule(ABC):
    module_type: str            # 'food' | 'grocery' | 'cab' | 'salon'
    router: APIRouter

    @abstractmethod
    async def create_order(self, payload, user, db): ...

    @abstractmethod
    async def get_order_status(self, order_id, db): ...

    @abstractmethod
    async def cancel_order(self, order_id, user, db): ...

# New module: just implement BaseServiceModule and register:
app.include_router(salon_router, prefix="/api/v1/salon")
